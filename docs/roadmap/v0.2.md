# Relay v0.2 Roadmap & Post-GA Planning

**Document ID:** `ROA-002`  
**Status:** Post-GA Development Roadmap  
**Target Window:** Q4 2026 – Q1 2027  
**Prerequisites:** Relay v0.1.0 General Availability & Commercial Launch  

---

## 1. Scope & Architectural Boundary

This document captures prioritized feature requests and architectural enhancements gathered from the **Extended Private Beta (EB001)**. In accordance with Relay's release discipline:
- **No v0.2 feature is backported to the frozen `v0.1.0` release line** unless required as an urgent backward-compatible security fix.
- The open-core Apache 2.0 foundation and the **"Payment Status ≠ Authorization Status"** invariant remain preserved across all future versions.

---

## 2. Prioritized v0.2 Feature Candidates

### 2.1 OS Isolation & Platform Parity
- **macOS Endpoint Security & Network Extension Sandbox:**  
  Develop an optional system extension utilizing Apple Endpoint Security (ES) and Network Extension (NE) frameworks to provide kernel-level socket isolation and loopback mediation on macOS, matching Linux Network Namespaces.
- **Windows AppContainer & WFP Isolation:**  
  Implement native Windows Filtering Platform (WFP) firewall rules and AppContainer isolation for external MCP child processes.

### 2.2 Enterprise Key Management & Hardware Security
- **Hardware Security Module (HSM) / PKCS#11 Provider:**  
  Support hardware-backed Ed25519 DSSE receipt signing via YubiKey, Nitrokey, and cloud HSMs (AWS CloudHSM, Google Cloud HSM).
- **Vault & Secrets Manager Plugins:**  
  Direct dynamic credential leasing integration with HashiCorp Vault, AWS Secrets Manager, and Azure Key Vault.

### 2.3 Extended Native Connectors
- **Kubernetes Native Connector:**  
  In-process connector mediating `kubectl` and Kubernetes API calls with namespace-scoped Cedar RBAC policies.
- **AWS Cloud Native Connector:**  
  Mediated AWS STS role assumption and IAM-governed API call mediation (S3, SQS, DynamoDB).
- **Redis / Memcached Connector:**  
  AST command-level parsing and Cedar ACL mediation for in-memory databases.

### 2.4 Policy Authoring & Enterprise Management UX
- **Interactive Cedar Policy Simulator:**  
  Web-based dry-run and visual simulation tool embedded in `relay ui` to test policies against historical action ledgers before deploying them.
- **Automated Policy Bundle Distribution:**  
  Signed GitOps policy synchronization for multi-node enterprise fleets without centralized telemetry.
- **SIEM / Splunk / Datadog Log Ingestion Adapters:**  
  Non-blocking background export daemon streaming signed DSSE receipts and Merkle checkpoints to enterprise SIEM platforms.

## 3. EB001-Informed Prioritization

**Runbook Phase:** 26 — v0.2 Product Planning  
**Source:** EB001 Extended Private Beta feedback (10 active orgs, 188 seats, 14,280+ governed actions)  
**Date:** 2026-09-14

EB001 customer feedback identified two dominant themes: **platform parity** (macOS/Windows isolation gap vs. Linux NetNS) and **enterprise key management** (hardware-backed signing, Vault integration). The following ranking reflects highest commercial and security value per cohort evidence.

### 3.1 Priority Ranking

| Rank | Feature | Category | EB001 Rationale |
| :---: | :--- | :--- | :--- |
| **1** | macOS Endpoint Security & Network Extension sandbox | Platform Parity | Most frequent cohort request; cooperative proxy mode insufficient for production MCP workloads on Apple Silicon fleets |
| **2** | Windows WFP/AppContainer isolation | Platform Parity | Second-highest platform friction; enterprise Windows Server 2022 deployments blocked by cooperative-only egress |
| **3** | HSM/PKCS#11 hardware-backed Ed25519 signing | Enterprise Key Management | Procurement requirement from 4/10 enterprise customers; receipt signing key extraction is top residual risk |
| **4** | HashiCorp Vault integration (dynamic credential leasing) | Enterprise Key Management | 3/10 customers requested Vault-native JIT broker; reduces encrypted-file vault operational burden |
| **5** | Kubernetes native connector | Extended Connectors | 2/10 customers running agent workloads in K8s; namespace-scoped Cedar RBAC is immediate production need |
| **6** | Interactive Cedar policy simulator | Policy Authoring UX | Reduces onboarding friction; 6/10 customers requested dry-run before production policy deploy |
| **7** | Asynchronous MCP Tasks | Protocol Expansion | Emerging MCP spec adoption; 1/10 early adopter requested background task mediation |
| **8** | Rust API encapsulation (`GovernedActionRunner` enforcement) | Developer Safety | Library misuse residual risk (GA004 limitation #4); lower urgency given CLI is fail-closed |

### 3.2 Deferred (Not v0.2.0 Scope)

The following candidates from §2 remain valuable but are deprioritized based on EB001 signal strength:

- AWS Cloud Native Connector (S3/SQS/DynamoDB) — no cohort demand in EB001 window
- Redis/Memcached Connector — no cohort demand
- Automated Policy Bundle Distribution (GitOps) — 1 customer interest; defer to v0.2.1
- SIEM/Splunk/Datadog adapters — enterprise interest but post-platform-parity

### 3.3 v0.2.0 Target Scope (Recommended)

Based on EB001 prioritization, **v0.2.0** should deliver:

1. **macOS network enforcement** (Rank 1)
2. **Windows WFP/AppContainer** (Rank 2)
3. **HSM/PKCS#11 provider** (Rank 3)

Vault integration (Rank 4) and Kubernetes connector (Rank 5) are strong candidates for **v0.2.1** if v0.2.0 platform parity work completes on schedule (Q4 2026 – Q1 2027 target window).

### 3.4 Constraints

- No v0.2 feature may weaken the **Payment Status ≠ Authorization Status** invariant
- No v0.2 feature may introduce product telemetry to the open-core binary
- Platform parity work must not regress Linux NetNS full-enforced mode
- All v0.2 features remain outside the frozen `v0.1.x` maintenance line

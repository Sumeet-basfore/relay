# Release Notes: Relay v0.1.0 (MVP Release Candidate)

**Version:** `0.1.0`  
**Status:** Release Candidate — Ready for Production Packaging & Distribution  
**Date:** 2026-09-14  

---

## 1. Overview

Relay `v0.1.0` is the initial production-distributable release candidate of Relay MVP.

Relay is a local-first, zero-trust MCP Security Gateway and Credential Broker delivered as a single, statically linked Rust binary (~14 MB) that interposes between AI agents and Model Context Protocol (MCP) tools.

---

## 2. Included Capabilities

### 2.1 Core Security & Protocol Gateway
- **Stdio MCP Gateway (`relay-mcp`):** Bounded JSON-RPC 2.0 streaming framing, line-delimited message framing, max frame bounds (4 MB), and protocol sanitization.
- **Subprocess Isolation (`relay-mcp`):** Automatic environment clearing (`env_clear()`) and strict system variable whitelisting, preventing ambient credential inheritance into child tool subprocesses.
- **RFC 8785 Canonicalization (`relay-canonical`):** Deterministic JSON Canonicalization Scheme (JCS) key sorting, number formatting, duplicate key rejection, lexical filesystem path normalization, and SQL AST normalization via `sqlparser-rs`.

### 2.2 Policy Enforcement & Approvals
- **AWS Cedar PEP Engine (`relay-policy`):** Embedded Cedar v4.0 evaluation with strict default-deny semantics, sub-2ms evaluation latency, and deterministic SHA-256 policy-set digest binding (SI-010).
- **Interactive Approval Provider (`relay-mcp`):** Direct `/dev/tty` human interactive approval prompts bound cryptographically to canonical `ActionHash`, with single-use nonce validation and headless fail-closed mode.

### 2.3 Just-In-Time Credential Broker
- **JIT Credential Broker (`relay-credentials`):** Ephemeral credential leasing on demand after policy authorization.
- **Provider Backends:** Native OS Keyring (macOS Keychain, Windows Credential Manager, Linux Secret Service), in-memory provider, and AES-256-GCM encrypted file fallback.
- **Memory Security:** Virtual memory page locking (`mlock`), zeroization on drop (`zeroize::Zeroize`), and custom `Debug` / `Display` redaction.

### 2.4 Native In-Process Connectors
- **Filesystem Connector (`relay.fs.*`):** Root jail enforcement, symlink traversal gate, special file blocking, and atomic writes.
- **PostgreSQL Connector (`relay.postgres.*`):** TLS-encrypted connection pool, SQL AST classification (DML vs DDL), statement cancellation timeouts, and JIT password injection.
- **GitHub Connector (`relay.github.*`):** REST API client pinned to `api.github.com`, redirect sanitization, response size limits, and JIT PAT injection.

### 2.5 Cryptographic Evidence & Hash-Chain Ledger
- **Action Receipts (`relay-receipts`):** RFC 9598 DSSE envelopes containing in-toto Statement v1.0 attestations signed with isolated Ed25519 node keys, featuring automated secret scrubbing before signing.
- **Append-Only SQLite Ledger (`relay-ledger`):** Cryptographic SHA-256 hash chaining ($H_i = \text{SHA256}(i \parallel H_{i-1} \parallel \text{PayloadHash}_i)$) with SQLite `BEFORE UPDATE` and `BEFORE DELETE` immutability triggers.
- **Offline Forensic Verifier:** `relay verify` validates full hash-chain continuity and digital signatures independently of the active gateway.

## 4. Known Limitations & Explicitly Deferred Capabilities

1. **Third-Party External Subprocess HTTP Egress:** The current MVP mediates all stdio MCP tool calls and native in-process connectors (FS, Postgres, GitHub). Third-party MCP child processes initiating raw outbound TCP/HTTPS requests independently are prevented from inheriting credentials via environment sanitization; full network packet interception requires the future loopback HTTP egress proxy (planned for a future milestone).
2. **Host Kernel Security Boundary:** Relay guarantees protection against compromised agents and unprivileged local users. Host root or kernel compromise is out of scope.
3. **Database Stored Procedures:** SQL query authorization parses statement ASTs; stored procedures configured with `SECURITY DEFINER` that perform internal mutations are subject to database-native access controls.

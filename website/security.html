Relay Security Center & Invariants

We believe that security software must be radically transparent about its threat model, trust assumptions, and cryptographic architecture.

Non-Interference Invariant: Payment status is never authorization status. Commercial license status cannot bypass Cedar policies, interactive approvals, or sandbox bounds.

1. Core Security Guarantees

  • Local-First Execution: The Relay daemon runs entirely on your local machine or private cloud infrastructure. No prompts, queries, or tool arguments are ever sent to Relay servers.
  • Zero Cloud Telemetry: Shipped release binaries contain no tracking SDKs, analytics beacons, or automatic update downloaders.
  • DSSE Ed25519 Receipts: Every mediated action is signed using in-toto DSSE envelopes, enabling independent offline verification with relay verify.
  • Anti-DNS Rebinding: The local web console strictly enforces Host: localhost or 127.0.0.1 and rejects all cross-origin state modifications.
  • PCI DSS Isolation: Commercial billing is handled 100% via Stripe. Relay servers never ingest, transmit, or store payment card numbers.

2. Commercial Control Plane Separation

A primary principle of Relay's architecture is that an attacker who compromises Relay's commercial website or billing system cannot gain control over local Relay instances:

  • Local Relay instances never poll or listen to Relay cloud servers.
  • There is no remote command channel or cloud-directed policy override.
  • Commercial entitlements use offline Ed25519 signatures verified locally against hardcoded public keys.

3. Security Disclosures & Bug Bounty

We welcome security researchers and operators to report vulnerabilities. Please report issues privately to security@relay.dev. See our full Vulnerability Disclosure Policy for PGP keys and response timelines.
